# 荣悦 E5 信息屏应用：代理（Nikki）、流量、在家、录音、助手、配额

给荣悦 E5 OpenWrt 的信息屏（机身上那块 320×480 小屏）用的两个应用，都可以直接在设备上操作，不用打开电脑或手机浏览器：

- **「代理」**（`nikki/`）：控制 [Nikki](https://github.com/nikkinikki-org/OpenWrt-nikki)（mihomo 透明代理）。
- **「流量」**（`dataplan/`）：自动发短信向运营商查询套餐，显示剩余流量（锁屏上也有），快用完时提醒，用完自动断开移动数据。
- **「在家」**（`homewifi/`）：能连上家里 WiFi 时，E5 关掉热点、改用家里网络（不耗 5G 流量，配合热点省电休眠）；家里 WiFi 断开后自动重新打开热点。

- **「录音」**（`recorder/`）+ 电脑端 **e5rec**（`e5rec/`）：机身麦克风分段录成 MP3，电脑自动同步、离线转文字，并提供 MCP 给 AI 查询。

各应用互不依赖，按需安装即可。

## 「代理」

### 功能

- **开关代理**：开启或关闭 Nikki。按钮显示 已开启 / 已关闭 / 启动中 / 停止中，要等透明代理真正接管流量后才显示"已开启"。
- **模式**：规则 / 全局 / 直连，切换立即生效，重启后保持。
  - 切到全局时，如果 `GLOBAL` 组选的是 `DIRECT`，会先自动把它指向主代理组。否则"全局"实际会让所有流量都走本地网络。
- **当前节点**：显示主分组最终用的节点（会顺着 节点选择 → 自动选择 → 具体节点 一路找下去）和上次测速结果。
- **切换节点**：订阅里所有可手动选择（Selector）的分组都会列出来，进去就能选节点、测延迟。
- **订阅**：列出全部订阅，显示正在用哪个、剩余流量、到期时间和上次更新时间；可以切换订阅，也可以更新订阅。
- 小屏上没有 emoji 字体，所以节点名前面的 🚀🇺🇸 这类图标在显示时会去掉，切换节点时用的仍是原来的完整名字。

添加新订阅请用 LuCI（服务 → Nikki → 配置文件）。在小屏上用按键输入长链接实在太难了。

### 操作

| 按键 | 作用 |
|---|---|
| ↑ / ↓ | 移动选择 |
| 确定 | 打开分组 / 选用节点 / 切换订阅 |
| ← / → | 在分组页里给选中的节点测延迟 |
| 返回 | 回到上一层 |

触摸也能用。

### 需要什么

- 已经装好 Nikki，并配好至少一个订阅：

  ```sh
  wget -O - https://github.com/nikkinikki-org/OpenWrt-nikki/raw/refs/heads/main/install.sh | ash
  ```

- 国内网络下 mihomo 第一次启动时，可能因为从 GitHub 下载 GeoIP 数据库超时而失败。解决办法：把电脑上 Clash 客户端的 `Country.mmdb`（改名为 `geoip.metadb`）和 `geosite.dat` 拷到 `/etc/nikki/run/`。
- 有的机场按 User-Agent 拦截：用 `clash.meta` 拉取会返回 Cloudflare 验证页或"访问受限"假节点。在 Nikki 里把订阅的 User-Agent 设成 `clash-verge/v2.4.2` 就能正常拉取。

### 实现

- `backend.uc`：信息屏后端以 root 身份运行的 ucode 路由。它通过 mihomo 的外部控制接口（`127.0.0.1:9090`）读取和切换节点，用 uci 和 `/etc/init.d/nikki` 处理开关、订阅和模式。
  - 控制接口的密钥只在后端使用，通过 curl 的 `-K -`（标准输入）传进去，不会出现在进程列表里。页面上只能看到分组和节点名。
  - 分组名和节点名先跟 mihomo 当前的数据核对，确认存在后才会用到；传给 shell 的内容一律加了引号。
  - 开关和切换订阅时会记下重启前的 mihomo PID，等新进程起来、`inet nikki` 的 nft 表建好后，才算启动完成。启动或停止期间的重复操作会被拒绝。
- `index.html`：页面本身，使用信息屏 SDK（`/sdk/e5.js`）处理按键，并调用后端接口。

## 「流量」

### 功能

- **向运营商查询**：定时（默认每 6 小时）发短信查询套餐，查询是免费的：电信发「108」到 10001，移动发「CXLL」到 10086，联通发「CXLL」到 10010。
  - 从回复中解析出通用流量的「共有 / 剩余」，再用它校准系统自带的流量统计（`unisoc.traffic`）：设置额度，修正本周期已用量。这样在手机上或 Android 下用掉的流量也会算进去。
  - 解析前会先去掉括号里的说明（例如"含上月结转 15.42GB"）；只讲定向流量的回复会被忽略；如果短信里总量、已用、剩余三个数都有，会检查它们能不能对上。
- **显示**：在应用里看剩余、已用、总量、今日用量、统计周期，以及运营商的回复原文。
- **锁屏**：锁屏上的用量框顶部多一行「套餐剩余 X GB · N%」和一根细进度条，快用完时变黄，用完时变红。
- **提醒**：剩余低于设定的百分比（5/10/20%）时，在信息屏上弹出通知。
- **用完自动断网**：用完后约 20 秒内断开移动数据，并亮屏通知；下个周期开始时自动接回。
  - 在应用里点「恢复上网」，本周期内就不再自动断网，以后可以随时重新开启。
  - 只撤销自己做过的断网。热点省电应用在热点关闭时用 `auto=0` 关掉的数据，它不会去碰。
- **出错时的处理**：
  - 查询失败后按 15 分钟、30 分钟、1 小时……逐步拉长间隔重试，不会连续发短信。
  - 新周期开始后等 3 小时再查，因为运营商月初的数据有延迟。
  - 系统时间没同步时不校准。
  - 读不到流量统计时什么都不改。

运营商的 "GB" 按 10⁹ 字节计算，这样屏幕、LuCI 和短信里的数字完全一致。如果运营商实际按 1024 计算，那么显示的剩余量会比实际少约 7%，断网只会提前，不会超额。

**不能短信查询的卡**（例如中国广电 46015：10099 不回复查流量指令，只能用 APP 或人工查）：在「高级」里设置「不能短信查询的卡：每月套餐流量」（GB）。
- 这类卡在上网时不会发查询短信，剩余量 = 设置的额度 − 本机统计的用量。
- 每月 1 号进入新周期时，额度自动设为"套餐额度 + 结转"。结转量是上月剩余，但不超过上月套餐本身的额度；结转可以在设置里关闭。
- 首月如果按天折算，可以用 `ubus call unisoc.traffic set` 直接给这张卡的槽位写入当月额度，新周期开始后自动改回每月额度。

**目前只用中国电信的真实回复测试过。** 移动和联通的回复格式如果不一样，查询会失败，应用会显示原因，但不会改动任何设置。

设置（查询开关、查询间隔、提醒阈值、自动断网）在信息屏的「高级」里，「流量」这一项下面。

### 实现

- `service.uc` + `dataplan.init`：procd 后台服务，每 20 秒检查一次是否超额，到时间就发短信查询。
  - 短信通过信息屏自己的 `/api/sms-send` 和 `/api/sms` 接口收发。
  - 断网用 `ifdown`，恢复用 `ubus network.interface up`，与状态看板上的「移动数据」开关是同一个接口。
  - 应用卸载后，服务会从 procd 注销、删除自己的 init 脚本，并把锁屏改动还原。
- `backend.uc`：屏幕页面和通知用的接口。它负责安装后台服务；服务代码有变化时会重启服务；锁屏那一行在系统升级后被覆盖掉，也会重新加回来。这些检查每分钟一次，挂在信息屏的通知轮询上执行。
- `lock-card.html`：锁屏那一行，插在信息屏页面 `index.html` 里 `app.js` 之后，和「热点省电」插 CPU 卡片的方式相同。
- `index.html`：应用页面。

## 「在家」

### 功能

- **在家**（E5 连着家里 WiFi）：热点关闭，E5 通过家里宽带上网。热点关闭后，「热点省电」会自动断开 5G 数据，熄屏后让设备休眠。
  - **判断离家**：家里 WiFi **连续断开 60 秒**才算离家，然后重新打开热点。
  - 只按醒着的时间计算：设备刚从休眠中醒来时，WiFi 会短暂断开，这次断开不计入。
  - "连上"指的是已关联、并且 WWAN 已经拿到地址。只关联上但拿不到地址的，不算连上。
- **在外**（热点开着）：E5 的无线芯片不能同时做热点和连 WiFi，开着热点时扫描不到家里 WiFi。
  - 所以只有看到**家附近的基站**时，才每 2.5 分钟暂停热点 3～4 秒去扫描一次。连续 3 次没找到，就改为每 10 分钟一次。
  - 家附近的基站是在家时自动记录的，不需要手动设置。
  - **离家较远时完全不扫描**，热点不会受到任何影响。
  - 扫到家里 WiFi（信号强于 −85 dBm）就切换过去。40 秒内没连上，就恢复热点，10 分钟内不再尝试。
- **防止来回切换**：
  - 连上家里 WiFi 后 10 分钟内又断开，会暂停自动回家 30 分钟。
  - 在家时手动打开热点，同样暂停 30 分钟。
  - 手动关闭热点（关闭无线）时，自动切换全部暂停。
- **保证有网**：
  - 每次切换后，都会确认热点确实已经在发射信号，否则重试。
  - 热点在配置上是开着的、实际却不在线时，后台会自动修复。
  - 扫描中途服务被停止或者应用被卸载，都会把热点恢复。
- **锁屏**：网络状态那一行显示「在家 · 已连 <WiFi 名>」或「· 在外」，不会增加锁屏的高度。
- **模式**：自动 / 一直在家 / 一直在外，在应用里或「高级」设置里切换。
- **旁路由（开关，默认关）**：在家时，把手机（或电脑）的网关和 DNS 设成 E5 的旁路由地址，就能自动翻墙，手机上不用开梯子 App。开关打开后，E5 会做以下几件事；关掉后全部撤销，恢复原样：
  - 在家里网段加一个固定地址：默认 x.x.x.253，会先检查有没有被占用，被占用就往下找，最低到 .240。这只是 wwan 的别名，**主路由器不用改任何设置**。
  - 防火墙只对家里网段放行 DNS 和 Nikki 的端口（53、1053、7890～7892），E5 的 SSH 和管理页面不对家里网开放。
  - 让 Nikki 接管从家里 WiFi 进来的流量。
  - 在家时持有唤醒锁，E5 不会深度休眠（否则旁路由就断了），所以在家时最好插着充电。
  - E5 带出门后，旁路由地址也就没了。改过网关的设备要把 WiFi 设置改回"自动（DHCP）"。

### 首次配置（一次性，用 SSH 执行）

家里 WiFi 的名称和密码只保存在设备的无线配置里，应用代码中不包含这些信息。

```sh
uci set network.wwan=interface; uci set network.wwan.proto=dhcp; uci set network.wwan.metric=20; uci commit network
uci add_list firewall.@zone[1].network=wwan; uci commit firewall          # @zone[1] 是 wan 区
uci set wireless.homewifi_sta=wifi-iface
uci set wireless.homewifi_sta.device=radio0; uci set wireless.homewifi_sta.mode=sta
uci set wireless.homewifi_sta.network=wwan;  uci set wireless.homewifi_sta.ifname=wlan0
uci set wireless.homewifi_sta.ssid='家里WiFi名'; uci set wireless.homewifi_sta.encryption=psk2
uci set wireless.homewifi_sta.key='家里WiFi密码'; uci set wireless.homewifi_sta.disabled=1
uci commit wireless
# 在家时保留短信和电话（热点省电默认的"关闭蜂窝"模式会让短信电话也收不到）：
uci set e5-plugin-hotspotdata.settings.mode=data; uci commit e5-plugin-hotspotdata
/etc/init.d/network reload; /etc/init.d/firewall reload
```

热点必须是 `wireless.default_radio0`（mode ap，ifname wlan0）。装好应用后，在家里点一次「立即检查家里 WiFi」：E5 会切到家里 WiFi，并开始记录家附近的基站。

### 实现

- `service.uc` + `homewifi.init`：procd 后台服务，每 15 秒执行一次状态机。
  - 切换方式：修改 uci 里两个 wifi-iface 的 `disabled`，然后依次执行 `wifi reload` 和 `wifi up radio0`。单独执行 `reload` 时，不会重新启动之前被 `wifi down` 停掉的无线芯片。
  - 扫描时先执行 `wifi down radio0`，再用 `iw` 扫描。比较 SSID 时会按照 `iw` 的转义规则处理，所以中文名称的 WiFi 也能匹配。
- `backend.uc`：负责状态查询、立即检查和切换模式；同时安装并维护后台服务（扫描进行中不会重启服务）。
- `lock-mark.html`：锁屏标识，插入到 `index.html` 中 `app.js` 之后；后台服务不在运行时不显示。
- `index.html`：应用页面。

## 「录音」+ 电脑端 e5rec

### E5 上（`recorder/`）

- 屏幕上一个按钮开始 / 停止；录音时**锁屏左上角显示红点和时长**。
- **侧键长按开关录音**：给系统自带的侧键应用（sidekey）加一个「开关录音」选项（设置 → 侧键 → 长按侧键）。开始时震一下，停止时震两下，熄屏状态下也能用。侧键应用是系统镜像自带的，镜像升级覆盖后，录音应用会在一分钟内自动重新加上；卸载录音应用时侧键会恢复为「开关热点」。
- 用系统自己的采集通路（`/opt/e5/e5-capture.py` 的 Capture 和音频硬件租约）录机身麦克风，经 libsndfile（LAME）直接编码成 MP3：48 kHz 单声道，约 33 kbps，**每小时约 15 MB**，CPU 占用约 9%。
- 按设定时长（默认 30 分钟）分段，写入 `/mnt/e5-data/e5rec/rec-日期-时间.mp3`（旁边一个 `.json` 记开始、时长、结束原因）。正在写的段是 `.mp3.part`。
- **来电**：通话会申请同一个硬件租约（最多等 5 秒），录音每 0.25 秒检查一次，立刻收尾这一段，挂断后自动接着录。开始录音失败时一定释放租约，不会挡住来电。
- 录音时持有唤醒锁，设备不深度休眠；服务被杀时 init 脚本的 `service_stopped` 也会释放。剩余空间低于 300 MB 自动停录。

### E5 上传到 NAS（推荐，1.3 起）

- 每段录完（分段可设 5 / 10 / 30 / 60 分钟）就由录音服务自己上传，**流量、WiFi 都行**，不用等回家或电脑开机。
- 上传：HTTPS PUT 到 NAS 的 `e5rec_server.py`（经公网 frp 隧道），只信任 NAS 自己的证书（`/etc/e5rec/nas.pem`，钉死），带口令；NAS 落盘（fsync）并核对 SHA-256 一致后才回 OK，**E5 收到 OK 才删本地文件**。重复上传幂等；失败按 15 秒起翻倍退避（最长 5 分钟）。上传时持有唤醒锁。
- E5 设置：`uci set e5-plugin-recorder.settings.upload_url=https://<公网地址>:<端口>`、`upload_token=<口令>`，证书放 `/etc/e5rec/nas.pem`。不设则不上传（仍可用电脑拉取）。
- 国内地址走 Nikki 的 `GEOIP,CN,DIRECT`，实测直连、不绕国外。

### NAS 上（`e5rec/e5rec_server.py`）

- 收到即转写：本地 silero VAD 切句（保留每句时间）→ 每句送 **DeepSeek 语音识别**（`api.deepseek.com/v1/tools/asr`，2026-11 官方新增；¥0.39/小时音频，按秒计）→ 某句失败时用本地 SenseVoice 兜底。VAD 切得很紧，**每句前补 0.8 秒、后补 0.4 秒**（不越过相邻句）再送，实测全对；不补会丢掉句首的字。
- 为什么不全在 NAS 本地识别：J3160（无 AVX）跑 SenseVoice 比实时慢 2.4 倍，跟不上连续录音；本地只跑 VAD 很轻。
- 部署：`e5rec/nas/e5rec-server.service`（systemd 用户服务，`E5REC_ROOT` 指录音目录）；`server.json` 放口令、证书路径；`~/.config/e5rec/config.json` 设 `"asr": "deepseek"` 和 `deepseek_api_key`（见 `config.example.json`）。
- MCP 直接跑在 NAS 上：`ssh nas 'cd … && E5REC_ROOT=… E5REC_NAS=1 exec .venv/bin/python -u mcp_server.py'`，数据只有 NAS 一份。

### 查看：E5 屏幕、手机/电脑网页、AI 总结（1.4 起）

- **AI 总结**（`e5sum.py`，DeepSeek `deepseek-flash`）：每段转写完自动生成标题、1–3 句摘要、要点、待办；每天一份当日总结（概括、时间线、待办，当天最多每 15 分钟更新一次）。没说话的段不调用。模型返回的不是 JSON 对象就当失败，同一段连续失败 3 次跳过，不挡后面的。
- **E5 屏幕**：录音应用按 → 进「转写」页：每天一行「AI 当日总结」，下面是当天各段（标题、时间、摘要、待办数）；确定打开看要点、待办和逐句全文；↑↓ 滚动，返回键回列表。经应用后端转发到 NAS（同一张钉死的证书和口令，口令放在 root 才能读的头文件里），每次结果都缓存，没网时显示上次的内容。
- **网页**（`web.html`，NAS 同一个端口 `/`）：密码登录，按日期翻看、搜索（高亮）、逐句时间可点、直接播放原声（支持拖动）。会话是服务端随机生成的，90 天；退出或改密码即失效。登录全局串行、失败后等待时间翻倍、连错 10 次锁 1 小时（frp 后所有客户端都是 127.0.0.1，没法按 IP 限）。自签证书，第一次访问请先核对指纹。
- 服务端同时最多 64 个请求，请求头 20 秒内必须收完。只读接口：`/v1/recent`、`/v1/rec/<名>`、`/v1/days`、`/v1/day/<日期>`、`/v1/search?q=`、`/v1/audio/<名>`（Bearer 口令或网页会话）。
- MCP 多了 `e5rec_summary`（某天的 AI 总结和待办）。

### 电脑上（`e5rec/`，可选的旧方式）

- `e5rec.py run`：找到 E5（先试 USB 192.168.9.1，再试上次的地址、邻居表里的 MAC，最后扫描局域网），用专用 SSH 密钥登录，**E5 的主机密钥首次连接后固定**（`~/.config/e5rec/known_hosts`）。
- 逐个文件：在 E5 上算 SHA-256 → 流式拉取边收边算 → 一致且已写入磁盘（fsync）后才删除 E5 上的文件。同名但内容不同的文件另存，不覆盖。
- 转文字同上（`asr` 不设时只用本地 SenseVoice），输出带时钟时间的 `.txt`、`.transcript.json`，并写入 SQLite 索引 `index.db`。连续失败 3 次的文件不再重试。
- systemd 用户定时器每 5 分钟跑一次（`e5rec/systemd/`）。用了 NAS 上传就停掉它，免得两边抢文件。
- `mcp_server.py`：stdio MCP，工具 `e5rec_status` / `e5rec_record` / `e5rec_sync_now` / `e5rec_list` / `e5rec_search` / `e5rec_transcript`。开始录音前要求 AI 先得到用户明确同意。

配置见 `e5rec/config.example.json`（复制到 `~/.config/e5rec/config.json`）：E5 的 MAC（热点和连家里 WiFi 时各一个），SenseVoice 模型和 silero_vad.onnx 的路径，以及转写方式。电脑拉取方式下，E5 上需把 `~/.ssh/e5_rec.pub` 加进 `/etc/dropbear/authorized_keys`。

**隐私**：录别人说话前请先征得同意。

## 「助手」：长按中间键问口袋语音助手（`assistant/`）

- 在任何界面**按住中间键**约 0.6 秒（可设 0.4–1 秒）：先显示「准备中」，麦克风真正打开时**震一下**，这时**就可以松手直接说**（1.9 起第一句也不用一直按着），说完停一下它就自己开始答。回答用喇叭念出来，问答显示在屏幕下方的卡片上，**底下一行紫色小字显示 DeepSeek 余额**。短按中间键照旧（按下的 Enter 原样还给当前界面）。
- 「说完」按声音判断：震动后先等 0.4 秒（不把马达声当成说话），连续 5 块（约 0.15 秒）够响才算开口、零星的响声不算；6 秒没开口就结束。
- NAS 上（`e5rec/e5assist.py`，`POST /v1/assistant`）：DeepSeek 识别 → `deepseek-flash` 回答（**开联网搜索**，能答天气新闻；附带最近几天录音的 AI 总结和最近两小时原话，能答「我今天答应了谁什么」；10 分钟内记得上下文，可以追问）→ DeepSeek 语音合成（女声 stella）。实测一问一答约 5–6 秒。
- **锁屏上也是全部权限**（1.9 起默认）：上下文、录音、录音工具都和解锁时一样，不用解锁。设置里打开「锁屏隐私」才回到旧行为（锁屏时不带录音和之前的对话）。联网搜索不准把录音内容写进搜索词。
- 录音中召唤：录音应用像让给来电一样让出麦克风，问完自动续录（让出标志 90 秒后自动失效，进程崩了也不会一直停录）。听的时候来电，助手立刻让出。
- 每次召唤有自己的编号，松手、取消只作用于这一次；第二次长按会先结束上一次；只关自己的播放（按文件找 aplay，不碰铃声）。
- **连续对话**（默认开）：答完自动接着听（震一下），直接说就能追问，不用再按键；按声音判断你说完了（本机麦克风实测：说话约 150–480、安静约 25–100，取「背景 2.5 倍且不低于 110」，静音 1.3 秒算说完，句间约 1.1 秒的停顿不会被切断）。6 秒不说话、按中间键或满 10 轮结束；整段对话期间录音一直让位。
- **回答音量**：E5 喇叭硬件增益被系统限制在原厂 Android 的水平（满级也就正常能听见），DeepSeek 合成的声音本身平均约 -19 dB；NAS 先放大再限幅（大声 +8 dB → 约 -12.7 dB，最大 +12 dB），不削波、不碰硬件上限。
- **工具（模型自己决定用不用、一层层用，一次回答最多 8 轮）**：
  - `web_search`：**自己的四引擎搜索**（Exa + Bing + SearXNG + Grok 并发去重，就是 Claude Desktop 用的 `…/websearch/search`，配置放 NAS 的 `websearch.json`，不进 git），全面但约 10 多秒；另有 DeepSeek 自带的快速搜索（天气这类）和读网页。
  - 录音**渐进式查看**（和 e5rec MCP 一个思路）：`recordings_days`（哪些天有录音、当日标题）→ `recordings_day`（当天总结和每段摘要、待办）→ `recordings_search`（全部录音逐句全文搜）→ `recordings_transcript`（读原文）。提示词里只放今天的总结和最近两小时原话，其余按需去查（只有开了「锁屏隐私」时锁屏上才不给录音工具）。
  - 实测：「今天下午录了什么」先查当天总结再读原文，16 秒；「全面查一下 DeepSeek 这个月的新功能」并发搜了 4 次，约 65 秒，答得全。
- **存到 Obsidian**：说「把这个存下来 / 记到笔记里」，它用 `save_note` 把要存的内容整理成一篇完整笔记，写进 Obsidian 库的 WebDAV 同步目录（remotely-save 的目标，明文、双向同步）下的 `E5助手/日期 标题.md`，不覆盖已有笔记；电脑和手机下次同步（最多 30 分钟）就能看到，电脑关着也能存。WebDAV 账号放 NAS 的 `obsidian-webdav.json`，不进 git。
- **回答用 MP3 下发**（E5 上有 PulseAudio 时）：48 kbps，约 WAV 的 1/8，不限长度的回答走流量也不重（5 分钟的回答从 14 MB 降到 2 MB 内）；没 PulseAudio 时退回 WAV（aplay 只认 WAV）。
- **卡片能翻、能跳过**：长回答在卡片里用 **↑↓ 翻看**（翻看时卡片不会自己消失）；正在朗读时**按一下中间键 = 跳过朗读、直接听你下一句**（连续对话关着时就是停止朗读）；其他时候按一下是关闭。
- **卡片上实时显示它在干什么**：NAS 的 `/v1/assistant` 加 `X-Stream: 1` 时按行推送进度（`{"progress": …}`，最后一行是答案），E5 边收边写状态：先显示听到的问题，再逐条显示「在想… / 四引擎搜索：… / 看 11-16 的录音总结 / 读录音原文 / 合成语音…」（最新一条带 ⏳，做完的打 ✓）；这期间按中间键也能立刻取消。
- **思考程度**（默认「最强」：`deepseek-flash` 思考强度 max，**不限回答长度**）。实测一个排日程的问题：不思考 1.5 秒只给大概；high 4 秒有理有据；max 11.6 秒排到每个小时。V4 Pro 慢且不更好，不提供。设置里可选 快速 / 标准 / 最强。
- 长回答按句**并行合成**再拼接（DeepSeek 允许同时 50 个）：28 秒的回答合成从 6.1 秒降到 1.9 秒。
- 设置：开关、思考程度、长按时长、连续对话、回答音量、锁屏隐私、喊名字召唤（先应答、唤醒词、灵敏度）。应用页显示最近的问答。

### 喊名字召唤：「贾维斯」「大肥鱼」（2.0 起，设置里打开）

- 喊「贾维斯」或「大肥鱼」，**震一下**就接着说；也可以一口气说完「贾维斯，明天几点开会」——唤醒词后面的话从同一段声音里直接切出来，不会漏掉开头。之后和长按召唤完全一样（卡片、回答、连续对话、锁屏全权限）；屏幕亮着时卡片自己弹出来，熄屏时只用声音答。
- **全在 E5 本机识别**：sherpa-onnx 的关键词检测（中英 3M zipformer 流式模型，int8），听到唤醒词之前一个字都不上传。唤醒词可选两个都用或只用一个；灵敏度三档（阈值 灵敏 0.12 / 标准 0.18 / 严格 0.25）。
- **喊完名字先应答**（2.1 起，默认开）：喊完名字停住时，它先说一句「我在，你说」（DeepSeek 女声，和回答一样放大过），说完再听你的问题——离得远也知道它在、可以开口了；它说这句时麦克风收到的声音丢掉，不会把自己的话当问题。喊完名字接着就在说（一口气）的话不插嘴，只震一下照常收。判断「接着在说」只看唤醒后新收到的 0.35 秒，不看唤醒词自己的尾音。
- **回答时喊名字能打断**（2.1 起）：助手念回答期间麦克风是空着的，唤醒检测继续听；这时喊「贾维斯」「大肥鱼」→ 立刻停掉朗读，照样先说「我在，你说」，再听新问题。防止被自己念的话叫醒：E5 采音本身会压低自己喇叭的声音；回答里本身带「贾维斯」「大肥鱼」字样时，这段朗读期间不检测；助手要开始听下一句（连续对话）时先打标记（`mic.want`），唤醒服务立刻让出麦克风。
- **和录音不抢麦克风**：录音开着时，录音应用把它录到的声音复制一份到管道（`/tmp/run/e5-wake/feed`，非阻塞、按整块写，没人读或满了就丢，绝不拖慢录音），录音照常；录音关着时唤醒服务自己占麦克风（同一个系统采集租约，来电、长按召唤一来立刻让出）。助手说话、思考、听下一句期间不检测，免得自己的声音把自己叫醒。
- **E5 麦克风很小声**（说话峰值只有满幅的 1–10%），模型要正常音量：检测前加自动增益（最近几秒最响处拉到 0.3，最多 32 倍，响声来了立刻降、之后每 2 秒回升一倍）。不加增益时喇叭放的唤醒词完全检测不到。
- **实测**：DeepSeek 合成的 12 句唤醒词命中 11 句；3.2 小时中文播客 + 22 分钟 E5 真实录音 **0 次误唤醒**；只有「大飞鱼」这种几乎同音的会被当成「大肥鱼」。真机注入测试：听到「贾维斯」→ 1 秒后卡片进入聆听 → 问题「今天天气怎么样？」一字不差 → 31 秒后回答。
- **代价**：检测进程常驻约 0.3 个核（E5 有 8 核，空闲 1.2 GHz 下）；**录音关着时它占着麦克风，E5 不能进深睡，更费电**（录音开着时本来就醒着，不额外费电）。不用就在设置里关掉。
- **运行时太大放不进应用包**（onnxruntime 34 MB，应用包上限 20 MB 解压后）：第一次打开时唤醒服务从 NAS 下载 `e5-kws-<版本>.tar.gz`（约 19 MB，用「录音」应用里的 NAS 地址、口令和钉死的证书，`GET /v1/kws/…`），**SHA-256 必须和 `wake.py` 里写死的一致**才装到 `/opt/e5-kws`。E5 是 musl，sherpa-onnx 官方包是 glibc：运行时自带 Debian arm64 的 glibc 加载器，用 `ld-linux-aarch64.so.1 --library-path` 启动。
- 运行时由 `assistant-src/wake/build-runtime.sh` 一条命令重建（下载 sherpa-onnx 官方包与模型、从 arm64 镜像取 glibc、用 zig 交叉编译 `kws.c`，同样输入出同样字节），产物也挂在 GitHub Release 上。

## 「配额」：quota-tray 看板，锁屏按 → 就能看（`aiquota/`）

- **数据就是 [quota-tray](https://github.com/hasakiikiiPRO/quota-tray) 看板的数据**：NAS 上跑 quota-tray 的 `quota-export.py`（拉取逻辑原样导入，只是不开界面），每 2 分钟写一份（`e5rec/nas/quota-export.service`，境外站点走 NAS 本机代理），e5rec-server 的 `GET /v1/quota` 带口令提供；E5 用「录音」应用里的 NAS 地址、口令和钉死的证书去取，后台每分钟最多一次，只有带账号的数据才替换缓存。Claude、Antigravity、Codex、xAI、WorkBuddy、大牛钱包、DeepSeek 都在。
- **界面照着看板做**：顶部「总账号 / 正常 / 受限」，**每类一个标签页**，顺序固定为 **Claude → DeepSeek → 全部 → 其余**（打开就停在 Claude），「周额度先用」推荐，账号卡片（状态点、名字、来源和站点标签、状态徽章；每个窗口的重置倒计时、百分比、进度条）。
- **按键**：锁屏按 → 打开；**←→ 切换类别，↑↓ 选账号，确定 展开详情**（完整账号、站点、状态、近 5 小时/近 7 天用量），再按确定收起；在第一个标签上按 ← 或按返回回到时钟。最上面有 **「立即刷新」**：↑ 选到它按确定，NAS 立刻重新拉取全部站点（约 5–30 秒，新数据到了自动换上；`POST /refresh` → NAS `POST /v1/quota/refresh`）。每次亮屏从时钟开始，电源键不变。解锁后也可以打开「配额」应用，按键一样。
- 两个页面由 `aiquota-src/dash.js` 一份组件生成（`python3 aiquota-src/build.py`），改界面只改这一处。

## 双卡：广电 / 移动卡要锁 5G 频段（`tools/`）

这台 E5 的基带有厂商配置错误：**广电、移动的卡如果 5G 频段同时开着 n28 和 n41（或者干脆不锁），一跑数据基带就崩溃重启**（`Modem Assert`，原因 `Drm allocate spr rf path fail`，原厂 Android 上也会）。表现是：显示 5G 已连接、拿到了 IP，但几秒到几分钟后就没网，信号显示 0%。依据：上游 [issue #15](https://github.com/sprd-linux-devs/e5-linux/issues/15) 与 FINDINGS §47.2。

解决办法是 **n28 / n41 只锁一个**。实测（广电卡在卡 2）：

| 5G 频段锁 | 结果 |
|---|---|
| 不锁 | 拿到 IP 后 1 秒崩溃 |
| n28 + n41 + n79 | 小流量能用，大流量下载时崩溃 |
| **只锁 n41** | 3 分钟 4 路大流量下载 427 MB（约 18 Mbps），0 次崩溃 |

设置命令（卡 2 的编号是 1；设置保存在 `/etc/unisoc-modem/lock-state.d/sim1/nr`，重启后保留）：

```sh
MU300_SIM_SLOT=1 /usr/libexec/unisoc-modem/lock-control apply nr 41
```

写入时会重启一次射频，当前上网卡会短暂断网。只锁 n41 时，没有 n41 信号的地方会退回 4G。电信卡（n78 / n1）不锁也一直正常。

`tools/sim-band-test.sh [频段] [秒数]` 在 E5 上自己完成整套测试，不需要电脑在线盯着：写频段锁并读回核对 → 切到卡 2 → 4 路大流量下载（默认 180 秒）→ 实时盯基带崩溃；**崩溃或没网就自动切回卡 1**，另有 10 分钟看门狗。结果在 `/tmp/gd3.log`、`/tmp/gd3.result`。测试时电脑别经 E5 上网，否则切卡时电脑也会断网。

## 共同

### 需要什么

荣悦 E5 上运行 [e5-linux](https://github.com/sprd-linux-devs/e5-linux) 的 OpenWrt，信息屏插件 API 版本 2。社区的 [e5-sleep 刷机包](https://github.com/CharlesGool/e5-openwrt-flasher) 也可以。

### 安装

从 [Releases](../../releases) 下载安装包，拷到设备上安装（以「流量」为例）：

```sh
scp -O dataplan-infoscreen-1.2.tar.gz root@192.168.9.1:/tmp/
ssh root@192.168.9.1 /usr/libexec/e5-infoscreen/plugin install /tmp/dataplan-infoscreen-1.2.tar.gz
```

也可以自己打包：在仓库根目录运行 `tar czf dataplan-infoscreen.tar.gz dataplan`（「代理」把 `dataplan` 换成 `nikki`）。

装好后在信息屏的应用列表里打开。应用装在 `/etc/e5-infoscreen/plugins/<id>`，升级系统镜像也会保留。卸载用 `/usr/libexec/e5-infoscreen/plugin remove <id>`。

两个应用的后端都以 root 运行（信息屏插件的通用规则）。装之前请先看过代码。
